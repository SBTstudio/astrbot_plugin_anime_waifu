## 零、安装与部署（换台机器 / 给别人用）

**需要**：AstrBot v3.x 以上（插件走 `Star` 接口），以及任意一个可用的消息平台适配。

### 三步装好

1. 把整个 `astrbot_plugin_anime_waifu/` 目录放进 AstrBot 的 `data/plugins/` 下。**整目录拷，别只拷 `main.py`**，`data/` 得跟着走。
2. 重启 AstrBot，或在面板「插件管理」里点重载。
3. 面板点开「二次元老婆抽卡」按需改次数 / 出率 / 冷却，保存后重载插件生效；**改角色库不需要重载**。

### 从 GitHub 拉（推荐）

```bash
cd AstrBot/data/plugins
git clone https://github.com/SBTstudio/astrbot_plugin_anime_waifu.git
```

之后 `git pull` 即可更新，面板重载插件生效。

> **关于 Release 里那个 300MB 的 zip**：仓库本身已包含全部文件（含本地立绘），**这个 zip 可以不下载**。
> 它只是给「不想用 git、想直接拷目录」的人准备的一键包，内容和仓库 `main` 分支一致。

### 包里都带了什么

| 内容 | 说明 |
|---|---|
| `main.py` / `metadata.yaml` / `_conf_schema.json` | 本体、插件信息、配置项定义 |
| `data/characters.json` | 2004 位角色全集（编号 / 作品 / 稀有度 / 简介 / 立绘） |
| `data/texts.json` | SSR / SR 文案与彩蛋表 |
| `data/images/`、`data/local_images/` | 随包分发的本地立绘，共 534 张（约 610MB），用相对路径引用 |
| `README.md` / `CHANGELOG.md` / `SR_RULE.md` | 文档、更新日志、文案撰写规则 |

**不带**：`waifu.db`（抽卡记录）和 `images.json`（立绘缓存）。这两个首次运行后会自动生成在 `plugin_data/astrbot_plugin_anime_waifu/`，属于各自机器自己的数据。

### 嫌大可以瘦身

本地立绘约 610MB。只留 `main.py` + `data/characters.json` + `data/texts.json`（约 20MB）也能跑：删掉 `data/local_images/` 后，对应的 534 位会回落到在线取图——首次慢 1~3 秒，其中一部分确实取不到图。

### 带上自己的收集记录（可选）

把旧机器的 `plugin_data/astrbot_plugin_anime_waifu/waifu.db` 拷到新机器同名目录，抽卡记录、收集进度、等级就都还在。

### 相对路径说明

`characters.json` 里的本地立绘写作 `data/images/xxx.png` 或 `data/local_images/<作品>/xxx.png`，插件按**自身所在目录**解析，所以插件放在哪、装在谁名下都不影响出图。写绝对路径也支持，但文件不存在时会自动回落在线取图，不会再出现"路径指过去却是空白"的情况。

## 二、卡池机制（双池）

角色库分**两个卡池**，抽卡时随机决定去哪个池：

| 卡池 | 内容 | 数量 | 每日次数（当前 / 默认） |
|---|---|---|---|
| **二游池** | 游戏作品（原神、星铁、绝区零、明日方舟、终末地、蔚蓝档案、东方、FGO……） | 1351 | **5 次 / 6 次** |
| **动漫池** | 动画 / 乐队企划 / 虚拟歌手（含 BanG Dream!、LoveLive!、世界计划、GIRLS BAND CRY、VOCALOID……） | 653 | **5 次 / 4 次** |

**抽取规则**

1. 每次抽取按比例随机决定卡池——当前配置是 **50% / 50%**（等概率；面板默认 60 / 40，可在配置里改）；
2. **某一池当日满额后，剩余次数只会出另一个池**——不会浪费机会；
3. 两池都满，才会提示"今天次数用完了"，并回显 `二游 x/5 · 动漫 y/5`（随配置变化）；
4. **「换二次元老婆」沿用上一抽所在的卡池**，不会靠换池刷次数。

> 分池的归属可在 `data/characters.json` 里用 `"pool"` 字段逐角色调整（`"game"` / `"anime"`）。

### 稀有度

| 星级 | 数量 | 抽取表现 |
|---|---|---|
| **SSR** | 101（二游 63 / 动漫 38） | 专属长文案 + 通用彩蛋句，部分角色附带"雪人歌" |
| **SR** | 317 | 一段 SR 专属短评 + 角色简介 |
| 普通 | 1559 | 一句百科简介（40~90 字） |

- 稀有度**不影响出率**，纯属文案规格差异——抽到就是抽到。
- `SSR排行` 只统计 SSR；`我的二次元老婆` / 图鉴则统计全部。
- `SSR排行` 表头给出本群参与人数、抽到过 SSR 的人数与全池收录进度；每人一行标注 `SSR 张数 / 总数（占比）`，占比＝该玩家 SSR 张数 ÷ 其已收集总数。
- `我的二次元老婆` / 图鉴会显示收集等级与升级进度（默认 25 位一级，可在设置里改 `level_step`）。

| **谁有二次元老婆** 〈名字 / 编号〉 | 谁有纸片人、查持有、持有查询、`shuiyou` | 看本群谁拥有这张卡、各自抽到的时间 |
| **SSR排行** | `ssr排行`、`ssrph`、SSR排行榜、二次元老婆SSR排行 | 本群 SSR 张数榜 + 明细（长则打包 md） |
| **我的二次元老婆图鉴** | 我的图鉴、我的收集、`wdtj` | 你收集过的全部角色，按作品分组（长则打包 md） |
| **二次元老婆帮助** | `anwhelp`、纸片人帮助 | 简短帮助 |
| **二次元老婆文档** | `anwdoc`、抽卡文档 | **群内速查表**（指令清单 + 实时配置概览，一条发出） |
| **重置二次元老婆记录** | `czanw` | 管理员专用，清空本会话记录 |

### 查询的三种打开方式

- **编号**：`42` / `c42` / `No.42` / `#42` / `编号42` / `42号` 都认；
- **单个命中**：给出完整介绍（SSR / SR 标记、入坑建议、同位体互提、粉毛三人组……）；
- **作品名命中 > 8 位**：不刷屏，直接打包成 `《作品》角色表.md`（编号 / 名字 / 星级）。

> **设计说明**：指令统一用「二次元老婆 / 纸片人」系列，是为了跟另一个抽群友的插件（`抽老婆` / `jrlp` / `今日老婆`）**共存不打架**。

**平台注意**：QQ 官方机器人在群里必须先 @ 才能收到消息，所以实际用法是 `@机器人 抽二次元老婆`。私聊直接发即可。

### 长内容怎么发

文本超过 **400 字**（图鉴、SSR 榜、作品角色表）时，自动打包成 `.md` 文件发送，正文只留一句说明。
理由很实在：QQ 被动回复超长会被直接从中间截断，宁可发文件也不给半句话。

## 四、配置项

面板路径：**配置 → 插件 → 二次元老婆抽卡**

| 配置项 | 类型 | 默认 | 说明 |
|---|---|---|---|
| **二游池每日次数** | int | `6`（现 **5**） | 游戏类角色卡池每天可抽次数，设 0 为不限 |
| **动漫池每日次数** | int | `4`（现 **5**） | 动漫类角色卡池每天可抽次数，设 0 为不限 |
| **二游池出率（%）** | int | `60`（现 **50**） | 每次抽取按此概率决定去哪个池；现值 50 即二游 / 动漫各半 |
| 抽取冷却（秒） | int | `30` | 两次抽取的最小间隔，设 0 为不限 |
| 查询冷却（秒） | int | `120` | `查二次元老婆` 的间隔，**与抽卡冷却分开计算**，设 0 为不限 |
| 允许重复抽到已拥有的角色 | bool | `false` | 关闭时优先从你未收集的角色中抽 |
| 抽卡时附带角色立绘 | bool | `true` | 关闭后纯文本，不联网、不消耗额外发送额度 |
| 取图超时（秒） | int | `20` | 超时自动降级为纯文本 |
| 排行榜显示人数 | int | `10` | 群排行最多显示几位 |
| 群聊白名单 | list | `[]` | 填写后仅这些群可用；留空不限 |
| 群聊黑名单 | list | `[]` | 这些群禁用 |

> 配置由 AstrBot 在启动时注入，**改配置需要重载插件**；而角色库（`characters.json` / `texts.json`）改完存盘即生效，见第七节。

## 五、立绘功能说明

### 图源策略

| 优先级 | 图源 | 说明 |
|---|---|---|
| 1 | **萌百指定的条目** | 角色数据里的 `moegirl` 字段（手工指定正确条目名，优先级最高） |
| 2 | **萌娘百科（直接）** | 定位页面信息框（`infobox-image-container`）取立绘，并叠加**文件名匹配**（如"明日方舟立绘_阿米娅_1.png"能对上"阿米娅"）；对 logo / 图标 / svg 扣分 |
| 3 | **萌娘百科（搜索兜底）** | 直接取不到时，用「角色名 + 作品名」搜索，**只接受「名字」或「名字(作品)」形式的条目** |
| 4 | **AniList** | 最后兜底。**必须通过名字校验**——结果的日文名、原名或别名中必须真的包含查询名（否则会出现"搜雷姆返回五条悟"的乌龙） |

> **宁缺毋滥**：搜索兜底会把「雷霆」匹配到游戏封面、把「萨莎」匹配到「萨莎的父亲」。
> 给错图比不给图更糟，所以过滤规则刻意写得很紧——只认「名字(作品)」这一种写法。

### 关于「无图」

抽到的角色没有配图，通常是这三个原因：

1. **萌百上是消歧义页**——名字被多个角色共用（如"阿狸""煌""时雨""尼禄"）；
2. **萌百没有独立条目**；
3. 网络异常/超时（**这种情况不会被永久记录**，下次抽到会自动重试）。

想给某个角色手工指定图源，在 `data/characters.json` 里给它加一个字段即可：

```json
{ "id": "c0312", "name": "萨莎", "series": "进击的巨人", "moegirl": "萨莎·布劳斯" }
```

### 缓存

- 缓存文件：`plugin_data/astrbot_plugin_anime_waifu/images.json`
- 键为角色 ID，值为图片直链
- **包含负缓存**：查过但确实没图的角色记为 `null`，不重复请求
- **网络失败不写负缓存**：一次没连上不等于永远没图
- 想强制全部重查：删除该文件即可

### 降级行为

以下任一情况都会**自动退回纯文本**，不会导致抽卡失败：

- 关闭了"附带角色立绘"
- 取图超时 / 网络不通 / 图源改版
- 找不到该角色的图
- 平台拒收图片（发送异常）

### 当前图况

`characters.json` 里带立绘 **1840 / 2004（约 92%）**——其中直链 1306 位、随插件分发的本地图 534 位；余下 164 位里，138 位靠运行时抓取，26 位标了 `no_image` 刻意不给图。


### 运行时数据目录

```
plugin_data/astrbot_plugin_anime_waifu/
├── waifu.db        抽卡记录（SQLite）
└── images.json     立绘缓存
```

### characters.json 格式

```json
[
  {
    "id": "c0001", "no": 1, "name": "沃雅妮莎", "series": "原神",
    "pool": "game", "ssr": true, "sr": false,
    "intro": "科洛列夫茨基剧团的首席女高音……",
    "image": "https://...", "baike": "沃雅妮莎"
  }
]
```

| 字段 | 说明 |
|---|---|
| `id` | 角色唯一编号，**一经使用不得更改**（见维护手册） |
| `no` | 展示用全局编号（`No.42`），与 `id` 数字部分一致 |
| `name` | 角色中文名，同时用于立绘检索与 `查二次元老婆` 匹配 |
| `series` | 所属作品，用于展示、搜索与图片文件名匹配 |
| `pool` | 卡池归属：`game` / `anime` |
| `ssr` / `sr` | 稀有度标记（可同时缺省＝普通） |
| `intro` | 一句百科简介，**SSR 文案缺写时的兜底来源** |
| `image` | 立绘地址：http 直链、**相对插件目录的路径**（如 `data/images/诀.png`）或绝对路径（可缺省；留空或文件不存在＝走运行时抓取） |
| `moegirl` | 可选，手工指定萌百条目名（现有 4 位用到） |
| `no_image` | 可选，`true` 表示**刻意不给图**（同名撞车防错图，现有 21 位） |
| `tip` | 可选，抽卡/查询时附加的一行提示（现有 159 位） |
| `baike` / `bwiki` / `prts` | 历史整理用的百科引用字段，运行时**不读取**，仅留档 |

### texts.json 结构

| 键 | 类型 | 用途 |
|---|---|---|
| `_SSR_TEXT` | dict | SSR 专属文案，键为 `名字` 或 `名字@作品` |
| `_SR_TEXT` | dict | SR 短评，键为名字 |
| `_PAIR_MENTION` / `_TWIN_MENTION` / `_PINK_TRIO` | dict | 同位体、双子、粉毛三人组的互相提及 |
| `_MHY_TWIN` | dict | 米哈游系影子 / 同位体的互相提及（代码已支持，**当前 texts.json 未填，暂不触发**） |
| `_TOUHOU_TIPS` | str | 东方角色通用提示 |
| `_SNOWMAN_HINT` | str | 雪人歌兜底提示 |

### waifu.db 表结构

```sql
CREATE TABLE draws (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    umo       TEXT NOT NULL,   -- 会话标识
    user_id   TEXT NOT NULL,   -- 用户 ID
    user_name TEXT,            -- 昵称（用于排行显示）
    char_id   TEXT NOT NULL,   -- 角色编号
    char_name TEXT NOT NULL,   -- 冗余存名字，便于历史记录展示
    series    TEXT NOT NULL,   -- 冗余存作品
    day       TEXT NOT NULL,   -- 日期（东八区 YYYY-MM-DD）
    ts        INTEGER NOT NULL -- 时间戳
);
```

> 排行榜按"**去重后的角色数**"排序，不是抽卡次数——抽得多不如抽得杂。

## 七、维护手册：怎么加角色

### 加角色的正确姿势

1. 打开 `data/characters.json`；
2. **取当前最大编号 + 1** 作为新角色 `no`（`id` 用 `c%04d` 同步生成）：

   ```python
   next_no = max(int(c.get("no", 0)) for c in chars) + 1
   ```

3. 补齐 `name` / `series` / `pool` / `intro`，需要的话加 `ssr`、`sr`、`image`；
4. **存盘即生效**——插件在每次抽卡 / 查询前比对文件指纹（时间戳 + 大小），
   变了才真读盘，平时零开销；读失败会保留旧数据并记 warning，不会崩。

> 配置类（上限、比例、冷却、黑白名单）不在此列，改完仍需重载一次。

### 三条铁律

1. **绝对不要给已有角色重新编号。**
   抽卡记录（`waifu.db`）和立绘缓存（`images.json`）都按 ID 索引。一改编号，历史记录就会"集体认错老婆"，缓存也会指向错误的角色。
   —— 这是一次真实事故的教训，当时差点毁掉 43 条抽卡记录和 39 条缓存。

2. **新角色的编号接着往下排**，不要复用已删除角色的编号。

3. **名字要唯一**。同名角色（跨作品）会被去重逻辑视作同一个，建议加区分；
   确实同名时，SSR 文案用 `名字@作品` 作键区分。

### 改完怎么验证

用抽卡记录做交叉校验（应全部吻合）：

```sql
-- 导出现有记录
SELECT DISTINCT char_id, char_name FROM draws;
```

再对照 `characters.json` 中同 ID 的 `name` 是否一致。0 条不匹配才算改对。

## 八、常见问题 FAQ

**Q：抽出来的角色没有配图？**
A：三种可能——① 该角色在萌百是消歧义页或没有独立条目；② 网络不通 / 取图超时；③ 你把"附带角色立绘"关掉了。可删除 `images.json` 后重抽一次强制重查。

**Q：抽一次卡，群里怎么发了两条消息？**
A：立绘和文字会被适配器拆成两条发送（媒体分片）。这**会消耗两次被动回复额度**。如果群里经常发不出，把"附带角色立绘"关掉即可。

**Q：提示"今天的次数都用完了"？**
A：看提示里的 `二游 x/5 · 动漫 y/5`。两池独立计算，当前每天各 5 次（面板默认二游 6 / 动漫 4）；某项设 0 表示不限。

**Q：图片点 `我的二次元老婆图鉴` 怎么收到一个文件？**
A：收集超过 400 字就会打包成 `<昵称>老婆图鉴.md`——不然会被平台截断。文件里带按作品统计与明细。

**Q：SSR 有什么实际好处？**
A：文案更厚（专属长评、彩蛋、部分角色有雪人歌），并计入 `SSR排行`。不提高出率。

**Q：为什么抽不到某某角色？**
A：两种可能——① 该角色不在库里（可以按维护手册自己加）；② 在库里但你已经抽到过——默认关闭重复，优先给你没有的。
**注意**：这是"优先不重复"，不是"绝对不重复"。

**Q：和抽群友那个插件（`jrlp`）会冲突吗？**
A：不会。指令名完全错开。

**Q：数据存在哪？重启会丢吗？**
A：`plugin_data/astrbot_plugin_anime_waifu/`，SQLite 存储，重启不丢。

**Q：能改成全角色、不限性别吗？**
A：可以，把角色加进 `characters.json` 即可。当前口径是只收女性，属于选择而非限制。

## 九、开发与自测

插件自带离线自测脚本（不依赖 AstrBot 运行环境，用桩替换接口）：

| 脚本 | 覆盖范围 |
|---|---|
| `anime_waifu_selftest.py` | 抽卡 / 去重 / 冷却 / 上限 / 换一个 / 排行 / 搜索 / 黑白名单 |
| `anime_waifu_selftest2.py` | 立绘提取（含真实抓取）/ AniList 名字校验 / 缓存读写 / 输出构造与降级 |

脚本位置：`workspaces/<会话>/backup/` 下。

### 关键逻辑说明

- **去重**：`pick()` 优先从未收集集合中随机；全部收集完才允许重复。
- **冷却**：抽卡与查询各自一套时间戳，互不影响。
- **每日次数**：按东八区日期、按池分别统计。
- **换一个**：`record(replace_last=True)` 会 **UPDATE 最后一条**，不新增记录，避免刷次数漏洞。
- **自动重载**：`_maybe_reload()` 比对 `characters.json` 的 `(mtime, size)`；`_maybe_reload_texts()` 同理。
- **长内容**：`_TXT_THRESHOLD = 400`，超过就走 markdown + `Comp.File`。
- **图片**：`resolve_image()` 惰性解析 + 写缓存；`_result()` 负责图 + 文 / 纯文的构造与降级。

## 十一、已知限制

1. **立绘首次取图需要联网**（1~3 秒），且部分角色确实没有可用图源。
2. **带图抽卡会发两条消息**，在 QQ 官方机器人上消耗两次被动回复额度。
3. **角色池需要手工维护**，没有自动同步任何在线数据库（在线源要么被墙、要么中文名覆盖不全）。
4. **"优先不重复"不等于"绝对不重复"**——全部收集完后会重新进入重复状态。
5. **不会因为个人偏好提高概率**；稀有度也不影响出率。
6. **配置改动需重载插件**（角色库不需要）。
7. 群聊场景下，若被动回复额度已耗尽，抽卡结果可能发送失败；此时应关闭立绘功能，或让对方重新 @ 一次。
